# 困惑度与突发性：检测原理与对抗口径

> 用途：解释「为什么句内微调有效」，并给出可量化的自检指标。不涉及任何检测平台的绕过手段，只讨论文本统计特征。

## 一、检测器在看什么

主流 AI 文本检测器（GPTZero、Originality.ai、ZeroGPT 一类）本质是**统计异常检测**，输入一段文本，输出「机器生成概率」。它们依赖的特征可归为三类：

| 特征族 | 具体指标 | AI 文本的典型表现 |
| --- | --- | --- |
| 困惑度类 | 逐 token 的平均负对数似然 | 偏低：选词是「最可能的那个词」 |
| 突发性类 | 句长 / 词频的波动幅度 | 偏低：句子长度、复杂度高度均匀 |
| 结构类 | 句式模板重复率、连接词密度、标点分布 | 偏高：模板句复用、逗号密度稳定 |

### 1. 困惑度（Perplexity）

定义：语言模型对一段文本的「意外程度」。设文本为 $w_1 \dots w_N$，

$$\mathrm{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log p(w_i \mid w_{<i})\right)$$

阅读方式：PPL 低 = 每个词都是模型预期之内的高频接续 = 文本「太好猜」。AI 生成文本天然 PPL 低，因为解码时就在最大化这个概率。人类写作会出现低频搭配、专业缩写、个人化语序，PPL 更高。

**可控手段**：不是去堆生僻字，而是恢复真实的专业表达——把「提出了一种有效的方法」写成「用残差连接替换了原解码器中的全连接层」。后者 PPL 更高，因为搭配更具体、更不可预测。

### 2. 突发性（Burstiness）

定义：句长（或句复杂度）的波动性。脚本采用的标准口径：

$$B = \frac{\sigma - \mu}{\sigma + \mu}$$

其中 $\mu$ 为句长均值，$\sigma$ 为句长标准差。另有变异系数 $CV = \sigma / \mu$，含义相近但更直观。

| 指标 | 人类学术写作 | AI 生成文本 | 判定线 |
| --- | --- | --- | --- |
| 句长标准差 $\sigma$ | 8–16 字 | 3–7 字 | <8 需处理 |
| 变异系数 $CV$ | 0.35–0.60 | 0.15–0.30 | <0.28 需处理 |
| 突发性 $B$ | -0.6 – 0.2 | -0.5 – -0.1（且更集中） | 仅作参考，中文短句多时 $B$ 天然偏负 |
| 短句占比（<12 字） | 15%–30% | <10% | <10% 说明缺少短句 |

> 注意：中文 $B$ 的绝对值普遍为负（因为 $\sigma < \mu$），不要用「$B$ 必须为正」这种英文语境的经验值判断。以 $CV$ 与短句占比为主。

### 3. 脚本里的实际算法

`scripts/ai_scan.py` 的段落风险分由三部分相加（上限 100）：

```
风险分 = 模式分(≤40) + 词表分(≤30) + 均一分(≤22)
```

- **模式分**：命中 `ai-pattern-taxonomy.md` 中 P01–P10 的模式，按权重累加，单项最多计 2 次。
- **词表分**：T1 词 ×12、T2 词 ×4、T3 词 ×1.5，按每百字密度折算，上限 30。
- **均一分**：$CV<0.18$ 计 22，$<0.28$ 计 14，$<0.38$ 计 6，否则 0。

分级：≥60 高，35–59 中，<35 低。

## 二、改写时怎么制造「人味」

五种可控手法，全部限制在句内，不推翻原段落：

### 手法 1：长短交错的节奏

把一段 3 句等长（各 20 字左右）改成 12 / 48 / 9 字的组合。长句承载机制说明（带插入语、破折号、括号补充），短句给结论。

### 手法 2：具体化替换抽象

| 抽象（AI 偏好） | 具体（人类写作） |
| --- | --- |
| 性能显著提升 | MSE 从 0.312 降到 0.245 |
| 有效缓解了该问题 | 长序列（>720 步）上的误差增长由 37% 收窄到 9% |
| 采用多种技术 | 使用滑动窗口 + 通道独立建模 + 门控融合 |

### 手法 3：保留作者的动作痕迹

在真正属于作者判断的地方插入第一人称视角：「我们最初尝试了……，但在……处失效」「本文刻意没有引入……，原因是……」。这类句子检测器几乎不会判为机器文本，因为它们包含不可预测的决断。

### 手法 4：容忍不对称与残缺

人类写作常有不完全对称的列举（只举两个、第三个用「等」），也会在句中改变叙述角度。不要为了工整把 2 项补成 3 项。

### 手法 5：去掉「完美过渡」

AI 偏爱「在此基础上」「与此同时」「由此可见」把段落焊死。人类写作允许硬切：上一段讲完模块设计，下一段直接「训练分两阶段进行。」——不需要过渡句。

## 三、与降重的冲突与调和

降 AI 要求「打散句式」，降重要求「换表达」，两者经常打架：过度换词会让文本更不自然，PPL 反而更低（因为用了通用同义词）。

调和口径：

| 场景 | 优先动作 |
| --- | --- |
| 连续 13 字以上与他人文献重合 | 先降重：语义改写 + 引用规范化（见 `references/strategy-plagiarism.md`） |
| 无重合但句式规整 | 只降 AI：句内重组，不动术语 |
| 既重合又规整 | 先改结构（换叙述顺序），再换词；顺序反了会做两遍工 |

**降重时禁止**：为躲重复把术语换成同义词（「注意力机制」→「关注力机制」），这会同时破坏专业性与可复现性，且检测器对这类异常搭配反而更敏感。

## 四、自检流程

```bash
# 1. 改写前基线
python scripts/ai_scan.py --docx paper.docx --out scan_before/

# 2. 改写后复测
python scripts/ai_scan.py --docx paper_v1.docx --out scan_after/

# 3. 对比两个 ai_scan.json 的 overall_score、cv、short_ratio
```

合格线（本技能内部口径，仅作趋势参考，不等于任何平台的真实检测结果）：

- `overall_score` 下降 ≥ 40%
- `cv` 上升且 ≥ 0.32
- `short_ratio` ≥ 0.12
- T1 词命中数 = 0

## 五、必须说清的三件事

1. **本技能不承诺任何平台的具体检测数值**。检测器模型、版本、阈值都在变，任何「保证降到 X%」的承诺都不可信。
2. **风险分是相对指标**，用于定位和验证改写方向，不能当作检测报告使用。
3. **改写之后必须重读**。统计指标合格但语义被改坏的段落，是这类工具最常见的失败模式；对照 `references/evaluation-criteria.md` 做人工复核是流程的强制环节。
