# 风险分级与默认扫描规则

> 用途：没有 AIGC / 查重报告时，用它决定「先改哪里、改到什么程度」。有报告时，报告优先。
> 章程：先高风险区、后低风险区；同一章内先改段首尾（最容易被检测器取样），再改中间。

## 一、章节优先级

| 级别 | 章节 | 为什么先改 | 允许的改动幅度 |
| --- | --- | --- | --- |
| P0 | 中文摘要、Abstract、总结与展望 / 结论 | 检测器与评阅人最先读、最常抽样；这些章节套话密度最高 | 句内重组 + 删套话 + 调句序，不改事实与数据 |
| P1 | 相关技术 / 文献综述、系统设计、数据库设计、功能展示、测试与评估 | 教材式段落多、模板句多，但术语密集 | 只做词句层处理；术语、模块名、表结构零改动 |
| P2 | 绪论、需求分析、研究意义 / 内容 / 创新点 | 口语化与政策腔多，但整体风险低于 P0 | 删口语、收评价性措辞，保留论证顺序 |

同优先级内，按正文章节顺序处理，便于在总揽文档里线性推进状态。

## 二、默认风险扫描清单

未提供报告时，必须主动扫出以下区域并在总揽文档中登记：

### P0 区（逐段过）

- 中文摘要：常见「背景—方法—结果—意义」四句闭环，结尾必带「具有重要意义」
- 英文摘要：与中文摘要同构，且常出现 "This paper" 开头 + 三个并列贡献
- 总结与展望：三点式展望（「未来将从三个方面展开」）、结论收满（「完全解决了」）

### P1 区（按模式筛）

- 相关技术：教材式定义句（「X 是一种基于 Y 的技术」）、无出处的「已有研究表明」
- 系统设计 / 数据库设计：表字段说明模板化（「该表用于存储……信息」）、「主要由……构成」
- 功能展示：页面作用 + 优点解释（「该页面……，使用户能够更直观地……」）
- 测试与评估：结论超出原型验证边界（「证明了系统可推广至……」）

### P2 区（抽检）

- 绪论：口语化（「有点麻烦」「帮了大忙」）、政策腔、三段式背景
- 需求分析：用例描述高度对称，每个用例都是「……，并支持……」
- 创新点：三点式 + 「首次提出」

## 三、典型改写信号（见到就动手）

1. 一句内「首先、其次、最后」齐全且结构对称
2. 技术介绍像公共教材条目，没有本文语境
3. 大量「本系统采用……并且……从而……」链条句
4. 页面 / 功能说明里出现「更直观、更方便、更清晰、一目了然」
5. 结论出现「具有重要意义」「提供实践参考」「奠定基础」
6. 每段长度接近，句长标准差 <8
7. 连续 3 句以「本文 / 本系统 / 该方法」开头

## 四、改写原则（最小干预）

- 优先句内重组：调语序、换连接词、拆合分句
- 局部替换强标记词，不做整段洗稿
- 控制过度解释：删掉「也就是说」「换句话说」后面重复同一意思的半句
- 收紧评价性措辞：无数据的评价一律降级或删除
- 保留技术事实、术语、图表编号、引用编号、数值

**红线**：不得为降 AI 引入语法错误、口语词、错误术语；不得改写实验数据与结论方向；不得删除必要的局限性说明（那反而是人类写作特征）。

## 五、与报告联动

提供检测报告时按以下顺序消费：

1. 报告给出「高风险片段」→ 直接定位到段落，优先处理
2. 报告给出整章重复率 → 该章整体按 P0 力度处理
3. 报告与默认扫描冲突（报告说低风险但命中多个 T1 词）→ 以默认扫描为准，因为报告可能只抽样了部分段落

报告解析支持三种格式（HTML 表格 / Markdown 表格 / 项目符号），`scripts/paper_pipeline.py` 会自动识别并把片段挂到对应章节任务文档。

## 六、段落保护清单（永不改写）

| 类型 | 例子 | 原因 |
| --- | --- | --- |
| 章节标题 | 「第三章 系统设计」 | 影响目录与交叉引用 |
| 图表题注 | 「图3-1 系统总体架构」 | 影响图表目录与编号 |
| 公式与编号 | 「式(3.2)」 | 影响公式引用 |
| 参考文献条目 | 「[1] 张三．……[J]．……」 | 影响查重与著录格式 |
| 页眉页脚 | 「硕士学位论文」 | 版式元素 |
| 表格单元格 | 字段名、类型 | 结构信息 |
| 含超链接 / 域代码的段落 | 目录域、交叉引用 | 改写会破坏域 |

脚本已按样式名与结构自动跳过上述对象；人工复核时若发现被改动，属缺陷，需回退该段。
